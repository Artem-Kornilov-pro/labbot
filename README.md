# LabBot — генератор лабораторных работ

Бот собирает лабораторную работу №2 по курсу «Алгоритмизация и программирование» по номеру варианта и ФИО:
две программы на C и отчёт `.docx`, оформленный по методичке. ИИ не используется — все тексты, код, формулы,
спецификации и тесты заготовлены заранее для каждой задачи, бот только подставляет данные студента.

## Что получает студент
- `lab2_part1.c` — часть I (матрицы, 17 задач), с проверкой ввода и циклами с досрочным выходом;
- `lab2_part2.c` — часть II (цифры чисел, 10 задач), только целые числа, без строк;
- `Лаба2_вариантN_Фамилия.docx` — отчёт: титульный лист (2 столбца оценок), автоматическое содержание (поле TOC),
  задание, постановка (Дано / Результат / При / Связь), метод решения (формулы Word), внешняя спецификация
  (фигуры Word), псевдокод, листинг, таблица тестов и распечатки работы программ.

Номера заданий: часть I — `(вариант mod 17) + 1`, часть II — `(вариант mod 10) + 1`; их можно поменять вручную.

## Запуск
```bash
cp .env.example .env        # вписать BOT_TOKEN от @BotFather
docker compose up -d --build
docker compose logs -f
```
Без Docker: `python -m venv .venv && .venv/bin/pip install -r requirements.txt && .venv/bin/python -m bot`.

## Лимит и база
Один пользователь может получить не больше `LAB_LIMIT` лаб (по умолчанию 2); `ADMIN_IDS` – Telegram id без лимита.
Каждая выданная лаба записывается в SQLite (`data/labbot.db`, в Docker – том `labbot-data`): Telegram id,
@username, ФИО, группа, преподаватель, лаба, вариант, номера заданий, время. Если генерация упала, лимит не тратится.
```bash
docker compose exec labbot python -c "import sqlite3; [print(r) for r in sqlite3.connect('data/labbot.db').execute('SELECT * FROM gens')]"
```

## Структура
```
bot/                 диалог бота (FSM): лаба → ФИО → группа → преподаватель → вариант → файлы
labgen/docx_engine.py    движок отчёта (стили, титульник, TOC, OMML-формулы, спецификация фигурами)
labgen/registry.py       список лаб, доступных в боте
labgen/labs/lab2/        лаба 2: common.py (C-каркас, ввод, эмулятор), inputs.py (наборы входных данных),
                         part1/tNN.py, part2/tNN.py — по файлу на задачу, report.py — сборка отчёта
tests/               проверки (нужен gcc и LibreOffice для части инструментов)
tools/               show_tests.py — результаты тестов задачи; check_overflow.py — поиск текста за полями
```

## Проверки
```bash
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
```
- каждая из 27 программ компилируется `gcc -Wall -Wextra -Werror` и на всех тестах печатает байт в байт то же,
  что эмулятор (по эмулятору бот строит таблицу тестов и распечатки, gcc на сервере не нужен);
- строки листинга и формул помещаются по ширине страницы;
- отчёты для вариантов 1–17 (покрывают все задачи) содержат поле оглавления, формулы и фигуры, без картинок.

## Как добавить задачу или лабу
Задача — модуль `labgen/labs/labN/partK/tNN.py` с объектом `TASK` (см. любой существующий: условие, Дано/Результат/При,
Связь, метод, окна спецификации, псевдокод, C-код, эмулятор, тесты). Новая лаба — пакет с функциями
`tasks_for_variant`, `task_texts`, `generate` и константами `TITLE`, `PARTS`, добавленный в `labgen/registry.py`.
