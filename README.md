# LabBot — генератор лабораторных работ

Бот собирает лабораторные работы по курсу «Алгоритмизация и программирование» по номеру варианта и ФИО:
программы на C и отчёт `.docx`, оформленный по методичке. ИИ не используется — все тексты, код, формулы,
спецификации и тесты заготовлены заранее для каждой задачи, бот только подставляет данные студента.

## Что получает студент
Лаба 2 «Алгоритмы с досрочным выходом из цикла. Алгоритмы обработки целых чисел»:
- `lab2_part1.c` — часть I (матрицы, 17 задач), с проверкой ввода и циклами с досрочным выходом;
- `lab2_part2.c` — часть II (цифры чисел, 10 задач), только целые числа, без строк;
- `Лаба2_вариантN_Фамилия.docx` — отчёт: титульный лист (2 столбца оценок), автоматическое содержание (поле TOC),
  задание, постановка (Дано / Результат / При / Связь), метод решения (формулы Word), внешняя спецификация
  (фигуры Word), псевдокод, листинг, таблица тестов и распечатки работы программ.

Лаба 3 «Использование функций» (ввод, обработка и вывод – отдельные функции, строка вместо числа и вещественное
вместо целого отклоняются):
- `lab3_part1.c` — часть I (10 задач): общая часть формулы оформлена одной функцией, вызываемой несколько раз;
- `lab3_part2.c` — часть II (9 задач): min/max по строкам или столбцам целочисленной матрицы;
- `lab3_part3.c` — часть III (7 задач): массив `A[0:n-1]` через указатель, функция подсчёта повторений и функция
  удаления сдвигом / формирования нового массива;
- `Лаба3_вариантN_Фамилия.docx` — отчёт на три программы (3 столбца оценок).

Лаба 4 «Обработка символьных строк» — одна программа `lab4.c` из трёх подпрограмм: выделение подстрок (12 вариантов),
поиск подстроки среди выделенных (10), преобразование строки, которой она принадлежит (11); ввод, анализ
существования результатов и вывод — в `main`. Строки в UTF-8 (русская буква — 2 байта), пробел считается буквой
при выделении подстрок и подсчёте букв. Отчёт `Лаба4_вариантN_Фамилия.docx`.

Лаба 5 «Программирование с использованием структурированных типов данных (файлы)»:
- `lab5_part1.c` — часть I (12 задач): числа с клавиатуры записываются в двоичный файл (`fwrite`), файл читается
  (`fread`) и по числам вычисляется величина по варианту (min/max, сумма, произведение, среднее, количество);
- `lab5_part2.c` — часть II (9 задач): текстовый файл из «Блокнота» (UTF-8, `\r\n` допускается) читается построчно,
  каждая строка преобразуется и пишется в новый файл, затем выходной файл выводится на экран; имена файлов
  вводит пользователь;
- `Лаба5_вариантN_Фамилия.docx` — отчёт на две программы.

Номера заданий в каждой части — `(вариант mod K) + 1`, где K — число заданий части (лаба 2: 17 и 10; лаба 3: 10, 9
и 7; лаба 4: 12, 10 и 11; лаба 5: 12 и 9); их можно поменять вручную.

## Запуск
```bash
cp .env.example .env        # вписать BOT_TOKEN от @BotFather
docker compose up -d --build
docker compose logs -f
```
Без Docker: `python -m venv .venv && .venv/bin/pip install -r requirements.txt && .venv/bin/python -m bot`.

## Лимит и база
Один пользователь может получить не больше `LAB_LIMIT` лаб (по умолчанию 2); `ADMIN_IDS` – Telegram id без лимита.
Каждая выданная лаба записывается в SQLite (`data/labbot.db`, в Docker – том `labbot-data`): Telegram id,
@username, ФИО, группа, преподаватель, лаба, вариант, номера заданий, время. Если генерация упала, лимит не тратится.
```bash
docker compose exec labbot python -c "import sqlite3; [print(r) for r in sqlite3.connect('data/labbot.db').execute('SELECT * FROM gens')]"
```

## Структура
```
bot/                 диалог бота (FSM): лаба → ФИО → группа → преподаватель → вариант → файлы
labgen/docx_engine.py    движок отчёта (стили, титульник, TOC, OMML-формулы, спецификация фигурами)
labgen/registry.py       список лаб, доступных в боте
labgen/labs/lab2/        лаба 2: common.py (C-каркас, ввод, эмулятор), inputs.py (наборы входных данных),
                         part1/tNN.py, part2/tNN.py — по файлу на задачу, report.py — сборка отчёта
labgen/labs/core/        общий каркас лаб 3–5: cio.py (ввод целых/вещественных/строк на C и копия на Python,
                         эмулятор консоли и файлов), task.py (описание задачи), report.py (сборка отчёта), omml.py
labgen/labs/lab3/        лаба 3: part1/tNN.py — по файлу на задачу; part2.py, part3.py — задачи по таблице параметров
labgen/labs/lab4/        лаба 4: pieces.py — подпрограммы трёх пунктов, __init__.py — сборка программы и тесты
                         (core/cstr.py — символы UTF-8, удаление/вставка сдвигом на C и Python)
labgen/labs/lab5/        лаба 5: part1.py (двоичный файл), part2.py (текстовый файл) – задачи по таблице параметров;
                         эмулятор хранит файлы в памяти, тесты C запускаются в отдельной папке с входными файлами
tests/               проверки (нужен gcc и LibreOffice для части инструментов)
tools/               show_tests.py — результаты тестов задачи; check_overflow.py [лабы] — поиск текста за полями
```

## Проверки
```bash
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
```
- каждая программа (лаба 2 – 27, лаба 3 – 26, лаба 4 – 12 сборок, в которых встречается каждая подпрограмма,
  лаба 5 – 21)
  компилируется `gcc -Wall -Wextra -Werror` и на всех тестах печатает байт в байт то же, что эмулятор (по эмулятору
  бот строит таблицу тестов и распечатки, gcc на сервере не нужен);
- строки листинга и формул помещаются по ширине страницы;
- отчёты для вариантов, покрывающих все задачи, содержат поле оглавления, формулы и фигуры, без картинок;
- в текстах отчёта нет случайной разметки (`*…*` – жирный, `_…_` – подчёркнутый).

## Как добавить задачу или лабу
Задача — объект `Task` из `labgen/labs/core/task.py` (см. `labgen/labs/lab3/part1/t01.py`: условие, Дано/Результат/При,
Связь, метод, окна спецификации, псевдокод, функции на C, эмулятор, тесты). Новая лаба — пакет с `LabInfo`
(цель, части, требования), функциями `tasks_for_variant`, `task_texts`, `generate` (`make_generate` из
`core/report.py`), `all_tasks` (для проверок) и константами `TITLE`, `PARTS`, добавленный в `labgen/registry.py`.
